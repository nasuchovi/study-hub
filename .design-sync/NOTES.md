# design-sync NOTES — 無法の国に生まれて

## このリポジトリの性質
- `study-hub` リポジトリ自体は静的HTML学習教材の置き場。デザインシステム同期の対象は
  アップロードされたゲーム単一ファイル **`無法の国に生まれて_v0.8.html`**（スマホ縦・
  テキスト×2D6ローグライク）と、その **デザインブリーフ**。
- ゲームは仕様上「出力はHTML/CSS/SVGのみ・画像ファイル不可・単一HTML運用」。よって
  Reactコンポーネント・ライブラリは存在しない。標準の design-sync 変換器（dist→bundle）は
  適用不可のため、**アップロード形式を手組み**した。

## 手組みの方針（＝標準同期との差分）
- `_ds_bundle.js` は生成していない。ライブReactバンドルの実体が無いため（原則「顧客が
  作っていないものを作らない」に従う）。
- 各コンポーネントはゲーム本体の**実マークアップ／SVGパス／CSSを忠実に移植**したもの。
  `.jsx` は外部依存の無い自己完結コンポーネントなので、デザインエージェントが自分の
  生成物にそのまま持ち込める。SVGパスは原典からバイト単位で写している。
- `_ds_sync.json`（同期アンカー）は省略。手組み層では story facts 等が揃わないため、
  省略が正直な選択（次回同期は全件を再検証する）。

## アップロード認証について
- claude.ai/code（Web）セッションからは DesignSync の書き込み権限が取れない
  （`/design-login` が対話ターミナル必須）。アップロードはユーザー側で
  「Send to Claude Code Web」経由か、`ds-bundle/` の直接読み込みで実施する。

## 再同期時の申し送り
- ゲームの新ビルド（v0.9 以降）が来たら、`ds-bundle/` の各コンポーネントを新ソースの
  該当マークアップと突き合わせて更新する。特にトークン（`:root`）・場面SVG（`SCENES`）・
  人影（`FIGURES`）・骰子の目配置（`PIP_POS`）・朱印の判定境界を確認。
- 朱印の判定境界（原典 rollFor 準拠）: raw=2→大失敗 / raw=12 または total≥tn+5→大成功 /
  total≥tn→成功 / それ以外→失敗。
